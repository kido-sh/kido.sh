kido
Docs GitHub

macOS command-line tools in tiny Darwin containers.

kido runs tools built for macOS on Apple Silicon in their own micro-VMs. Each container boots an open-source Darwin guest in under a second. No root, and no Linux VM in between.

curl -fsSL https://kido.sh/install.sh | sh

Or brew install kido-sh/tap/kido, or build from source.

$ kido run --rm darwin uname -sm
Darwin arm64
$ kido build -t adb:37 adb-image/
Successfully tagged adb:37
$ kido run --rm adb:37
Android Debug Bridge version 1.0.41

What you get

Fast

A one-shot kido run --rm takes under a second. kido cp moves 64 MB in about a second or less.

Everyday commands

run, exec, cp, logs, commit, build from a Dockerfile, push and pull through any OCI registry.

Isolated

Every container is its own virtual machine. The host talks to its guest agent over a mutually authenticated, encrypted channel.

Networks

User networks that cannot reach each other, --network none, and published ports on 127.0.0.1 by default.

Two backends

Apple's Virtualization.framework by default, or QEMU with Hypervisor.framework.

Unmodified binaries

Tools built for macOS arm64 run as they are: no rebuild, no shims.

Status

kido is experimental. Commands, the image format and the protocol between kido and its guest agent may still change. The first release and a downloadable base image are on their way; until then, build kido from source. Read the README for setup, the security model and current limits.

kido is open source under the Apache License 2.0. Its guest builds on PureDarwin, xnu-loader and Apple's open-source Darwin releases: see the acknowledgements.
